# excel-vba-charts

仅含 **VBA 模块（`.bas`）** 与说明；仓库不提交 `.xlsm`。在 Windows Excel（VBA7）中新建工作簿，通过 **VBA 编辑器 → 文件 → 导入文件** 导入下列模块，保存为启用宏的工作簿后使用。

**导入顺序建议**：`modConfig` → `modPivot` → `modStaging` → `modCharts` → `modMain`（或一次性全选导入亦可）。

## 流程概览

1. 你在工作簿中 **自行准备数据源** 并 **创建/维护透视表**（见下文布局要求）。
2. 在 **`modConfig.bas`** 中确认 **`PIVOT_SHEET`**、**`PIVOT_TABLE_NAME`** 与工作簿中的工作表名、透视表名一致。
3. 运行 **`modMain.Run_Pipeline`**：
   - **`modPivot.RefreshExistingPivot`**：刷新透视缓存（`PivotCache.Refresh`），并 **校验** 列/值与行区数量（至少 1 个行字段）；
   - **`modStaging.BuildStagingWide`**：从透视 **数据区** 读出数值，生成 **Staging 宽表**（`tblStage`），支持 **多个行字段**；可选按规则合并小额客户列；
   - **`modCharts.BuildOrRefreshChart`**：在 **`图表`** 工作表上创建/替换 **`chtStagingStack`**（堆叠柱形），数据源为 **`tblStage`**。

本仓库 **不包含** 明细清洗与程序化创建透视表的代码。

## 透视布局要求

| 区域 | 要求 |
|------|------|
| **行** | **至少 1 个**行字段；**个数与顺序**由你决定。宽表与图表中，**从左到右** 与透视 **行区字段顺序** 一致：第 1 个行字段为最外层分类，**最后一个行字段为最内层**（横轴上最细的分类粒度）；各 **客户** 仍为堆叠系列（及可选合并列）。 |
| **列** | **恰好 1 个**列字段，且字段源名须为 **`客户`**（与 `modConfig.COL_CUSTOMER` 一致，可在配置中改名）。 |
| **值** | **恰好 1 个**度量，须基于字段 **`收入`**（`COL_REVENUE`），且聚合为 **求和**。 |

布局不符合时，运行会在 **`Run_Pipeline`** 中 **报错中止**（错误描述为中文）。

运行入口宏时会 **自动刷新透视**；日常在界面中修改数据源后，也请先 **刷新透视** 再运行宏，以免读到旧缓存。

## Staging 与小额合并（`modConfig`）

- 每一 **行键** = 透视中 **一行标签** 的完整组合（各层行标签用内部 Tab 拼接）；合并与 Top N 均在 **同一行键** 下、按各 **客户** 列进行。
- **`ENABLE_CUSTOMER_MERGE`**：`False` 时不写合并列，仅输出宽表。
- **`MERGE_COL_CAPTION`**：合并列标题（默认 `其他（客户小额）`），开启时一般在 **最右侧**。
- **Top N**：按 **`|值|`** 从大到小；前 **`MERGE_PROTECT_TOP_N`** 名永不并入合并列；第 N 名处 **`|值|` 并列** 的客户 **全部保护**。`|v|` 相同则按 **客户名** 字典序（与 **`MERGE_TIE_BREAK`** 语义一致）。
- **OR 合并**：未保护客户若 **`|v| < A`**（`MERGE_ABS_THRESHOLD`）或（**`T>0`** 且 **`|v| < T·p`**）（`MERGE_PCT`），则并入合并列。`T` 由 **`MERGE_PCT_DENOM`**（`AbsSum` / `NetAbs` / `PosSum`）按 **该行全部客户列（含 0）** 计算；**`T=0`** 时占比项不成立，仍可能仅因 **`|v|<A`** 被合并。
- 客户列顺序：按全局 **`|收入|` 之和** 从大到小，再按客户名字典序。

## 图表说明

- 类型：**堆叠柱形图**（`xlColumnStacked`），`SetSourceData` 指向 **`tblStage` 整块区域**（含表头），`PlotBy:=xlColumns`。
- **多级分类**：表头 **前 N 列**（N = 透视行字段数）为分类轴层级；Excel 通常将 **最左列为最外**、向右逐层 **内推**，故 **最右一列** 对应透视 **最后一个行字段**（最细粒度），其下堆叠各客户系列。
- 数值轴：尽量保证 **比例轴穿过 0**（全正/全负时的边界处理见实现）。
- **`SHOW_DATA_LABELS`** / **`CAT_LABEL_ANGLE`**：数据标签与分类轴标签角度。

## 宏安全

1. 将上述 `.bas` 导入标准模块。  
2. 保存为 **`.xlsm`**（或启用宏的格式）。  
3. 在 **信任中心** 中按策略允许运行宏。

## 排错摘要

| 现象 | 可能原因 |
|------|-----------|
| 未找到透视表 | `PIVOT_SHEET` / `PIVOT_TABLE_NAME` 与工作簿不一致 |
| 透视刷新失败 | 数据源区域无效、字段被删或缓存损坏 |
| 校验失败 | 列不是「客户」、值不是「收入」求和、行区为空 |
| Staging 为空 | 无数据区、`PivotCell` 行项数与行字段数不一致（布局异常） |
| 图表未更新 | `STAGING_SHEET` / `STAGING_LIST` 与配置不一致 |

## Mac Excel

VBA、透视与图表在 Mac 上可能与 Windows 有差异；建议以 **Windows Excel** 为主验证。若 `PivotCell` 报错，请记录版本号。
